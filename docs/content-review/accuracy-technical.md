This page makes the most specific, falsifiable claims on the site. Each stack/table row was checked directly against `requirements.txt`, `frontend/package.json`, `AGENTS.md`, and backend source.

- **Frontend: React, TypeScript, Vite, Radix UI, Tailwind CSS 4** — confirmed: `frontend/package.json` has `tailwindcss: 4.1.12`, `@tailwindcss/vite`, and numerous `@radix-ui/react-*` packages, Vite build/dev scripts.
- **Dev defaults: backend :10000, Mission Control :3000 (proxies /api)** — confirmed exactly in `AGENTS.md` ("FastAPI backend (port 10000)... React+Vite Mission Control frontend (port 3000)... proxies /api to backend:10000").
- **MC engine: "Twelve-bin meta-cognitive scoring; promotion at MC ≥ 8.5"** — confirmed: `backend/systems/mc_engine.py` docstring ("MC Engine & 12-Bin System"), `docs/JANUS_OS_LAYERS.md` ("12-bin meta-cognitive scoring"), consistent 8.5 threshold across `memory_block.py`, `FRONTEND_SPEC.md`, `.cursor/rules/01-caretaker-lane.mdc`.

- **Assembly line: "Six-agent pipeline"** — confirmed: `Caretaker → Gardener → Mercury → Sentinel → Conductor → Scribe`, named identically across `README.md`, `AGENTS.md`, `.cursor/rules/00-janus-orientation.mdc`, `cli/commands/agents.py` (`_AGENT_NAMES`).
- **Gate outcome table (Allow / Clarify / Human review / Allow with debt / Block)** — confirmed **exactly** against `vaults/ltmvault/doctrine/dtm_gate_contract.md`'s "frozen Janus OS outcomes": `allow`, `clarify`, `block`, `human_review`, `allow_with_debt`.
- **"MC scoring informs readiness. The gate authorizes. That separation..."** — matches `docs/JANUS_OS_LAYERS.md` phrasing almost verbatim ("MC engine... gate vs confidence separation") and the gate contract doc ("MC scores readiness; the gate is the authorization layer above MC").

## Needs update / accuracy gaps
- **Ritual sequence lists "negotiate" as a distinct stage: "intake → refine intent → plan → negotiate → approve → apply → verify → publish."** The current, canonical `WorkflowStage` enum in `backend/janus/app/services/workflow_contract.py` has **no `negotiate` stage** — it is `INTAKE, REFINE_INTENT, PLAN, APPROVE, APPLY, VERIFY, PUBLISH` (7 stages, not 8). A "negotiate" stage does appear in one doc, `docs/stage_1_contract_SUPERSEDED_2026-04-13.md` — which is explicitly marked **SUPERSEDED**. In current code, negotiation is folded into the `refine_intent` stage (e.g. `negotiated_content_hash` lives under `stage_data.refine_intent`), not a standalone step. **Recommend:** drop "negotiate" from the public ritual sequence, or reword to "intake → refine intent (including negotiation) → plan → approve → apply → verify → publish" to match the live contract.
- **Sentinel's role is stated as "Policy audit — PII, safety, compliance."** The authoritative code-truth doc (`docs/GAP_ANALYSIS_SYSTEMS_WORKFLOW_MVP.md`) explicitly flags this exact wording as outdated: *"Not a binary 'Sentinel never does policy.' In code, `SentinelAgent` is epistemic-first (heuristics + judge). Broader PII / safety story may still live in other layers or older doctrine; this is naming and SSOT work."* In other words, today's `SentinelAgent` implementation is primarily an epistemic/heuristic + LLM-judge check, not a dedicated PII/safety/compliance auditor. **Recommend:** either update the website copy to describe Sentinel's actual current behavior, or treat "PII, safety, compliance" as the target design and note it's still converging in code.
- **Embeddings row: "nomic-embed-text; SentenceTransformers fallback (all-MiniLM-L6-v2)" next to "Vector memory: ChromaDB — 384-dimensional embeddings."** The real provider order in `backend/janus/app/services/vector_indexing/embedding_service.py` is: **OpenAI (if configured) → Ollama `nomic-embed-text` (768-dim, only if `LOCAL_LLM_BASE_URL` is reachable) → SentenceTransformers `all-MiniLM-L6-v2` (384-dim, offline fallback)**. Two issues: (1) the site's embeddings row doesn't mention OpenAI as a possible first-choice provider; (2) listing `nomic-embed-text` first implies it's the primary/default, but per `docs/JANUS_SYSTEM_SNAPSHOT.md` and `docs/runtime_truth_pack_2026-04-13.md`, the **actual default in recorded runtime snapshots is SentenceTransformers at 384-dim** (Ollama not connected in those runs) — which is also the dimension count the page's "Vector memory" row headlines. **Recommend:** clarify that 384-dim/SentenceTransformers is the current default fallback, and nomic-embed-text (768-dim via Ollama) only applies when a local Ollama endpoint is configured and reachable.
- **Proof section: "After seeding twenty-six company hygiene cards..."** Could not confirm the literal number **26** anywhere in the current codebase or dogfood docs (searched `operator_dtm_hygiene_seed.py`, `docs/dogfood/*`). Card IDs referenced in code go at least to `H-23` and `DTM-HYGIENE-T2-007`, so the total count plausibly could be around that range, but the exact "26" figure is unverified and may have drifted as hygiene cards were added/removed over time. **Recommend:** re-run `make dogfood-seed` and confirm the current card count before publishing, or drop the specific number and say "the full DTM company hygiene card set."
- **Card hierarchy: "When documentation changes at the parent, dependent cards are notified."** No specific notification/propagation mechanism for parent-doc-changes was found in the codebase (searched for notify/dependent-card patterns). The closest matches are general "notify human" auto-action patterns for unrelated flows. This claim may be describing an intended/aspirational behavior rather than a shipped mechanism. **Recommend:** verify whether this notification actually fires today, or soften the claim to describe gate/governance inheritance only (which *is* confirmed) without the specific "notified on doc change" mechanic.

## Unverified (lower priority)

This isn't contradicted by the site copy, but it's worth knowing: most of the "assembly line" is currently rule-based rather than model-driven, which actually reinforces (rather than undermines) the site's "deterministic, auditable" positioning.
